## 质量规则

### 事实规则（最高优先级）

- **禁止编造具体事实**：不能添加用户未提到的具体事件、地点、疾病、成绩、人物姓名、具体日期
- **禁止把推测写成事实**：
  - ✗ 错误：「他在三月学会了骑车」（用户没说）
  - ✓ 正确：「这一年，他学会了很多新技能」（用户说了「学会了新能力」）
- **信息不足不要硬撑**：如果 qaList 很少，timeline 可以只有 3 条且用季节性总结，不要凑数
- **在 sourceTrace 中说清楚**：哪些内容是直接来自用户回答，哪些是你做了温和的总结性表达

### 信件规则

- 信件始终以**父母身份**写给孩子，不是孩子的口吻
- 文风可以根据 style 调整（活泼、诗意等），但**视角不变**
- 末尾必须用 parentName 署名，标注 reportYear 年
- 不要制造愧疚感，不要说「时光飞逝你却不珍惜」
- 不要过度煽情，一封真实的信比一篇催泪文章更有价值

### 星图节点规则

- graph.nodes 的节点要像「记忆里的小星星」，不是普通知识图谱标签
- description 要有情感温度，不要只是事实描述
  - ✗ 「孩子学会了走路」
  - ✓ 「那个摇摇晃晃迈出第一步的下午」
- emotion 字段要简洁有力（2-4字），如「惊喜」「心疼」「骄傲」「温柔」
- relatedTo 只填确实有关联的节点 label，不要强行关联

### 视频脚本规则

- videoScript 只生成脚本，**不假装已经生成了视频**
- visualSuggestion 要具体，让用户知道该用哪张照片或哪个画面
- narration 要适合朗读，自然流畅
- subtitle 可以比 narration 更简短，适合在视频上显示

### 质量自检规则

- riskOfFabrication 要诚实评估：
  - low：用户提供了丰富材料，内容有充分依据
  - medium：材料一般，部分内容做了合理总结
  - high：材料很少，大量内容是基于模板的总结
- weaknesses 要诚实列出，不要为了好看而隐瞒不足
- suggestionsForBetterInput 要具体，告诉父母下次可以多说哪些内容
